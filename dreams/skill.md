# SKILL: LLM Instrument Control & Reproducible Data Analysis

Use this skill when tasked with controlling hardware/instruments, acquiring data, or performing data analysis pipelines where **reproducibility without an agent in the loop** is required.

---

## Core Architecture Principles

1. **Strict Separation of Concerns**:
   - **LLM Role**: Acts strictly as an orchestrator and code generator. The LLM **never** processes raw data arrays, does math internally, or manipulates raw data directly in prompt memory.
   - **Execution Engine**: Runs generated Python code locally to drive hardware and process data.
   - **Data Artifacts**: Raw data and execution scripts are saved explicitly to disk so any run can be re-executed deterministically without calling the LLM again.

2. **The 3-Artifact Rule**:
   Every instrument session or experiment run MUST generate three self-contained artifacts in a dedicated run directory (`/runs/YYYY-MM-DD_HH-MM-SS/`):
   - `config.json`: Metadata, channel settings, hardware parameters, environment info.
   - `raw_data.hdf5` (or `.parquet` / `.csv`): Unmodified raw hardware output.
   - `analysis.py`: Standalone, executable Python script containing all filtering, math, statistical operations, and plotting logic.

---

## Code Generation Guidelines

When generating control and analysis code for instruments, adhere to these strict rules:

### 1. Hardware Control (`acquisition.py`)
- Standardize hardware drivers around robust protocols (e.g., `PyVISA`, `pyserial`, or explicit SCPI wrappers).
- Keep acquisition routines lean: set parameters, trigger acquisition, fetch data, save to `raw_data.hdf5`, and release hardware locks immediately.
- Always include error handling and explicit hardware cleanup (`instrument.close()`) in `finally:` blocks.

### 2. Standalone Analysis (`analysis.py`)
- **Self-Contained Execution**: Must accept command-line arguments for input file paths (`--input raw_data.hdf5`, `--output-dir ./results`).
- **Standard Libraries Only**: Use deterministic, standard scientific Python libraries: `numpy`, `scipy`, `pandas`, `matplotlib`, `h5py`.
- **Fixed Seeds**: Include explicit random seeds (`np.random.seed(42)`) if fitting or stochastic steps are used.
- **No Agent Dependencies**: Must run successfully via standard command line (`python analysis.py --input raw_data.hdf5`) without any special agent framework, LLM API keys, or network connections.

## Step-by-Step Execution Workflow

When fulfilling a user request for instrument control or data processing:

```
[1. User Intent] ──> [2. Generate acquisition.py & analysis.py]
                             │
                             ├──> [3. Execute acquisition.py] ──> Raw Hardware Data
                             │                                           │
                             └──> [4. Execute analysis.py] <─────────────┘
                                         │
                                         v
                            [5. Standalone Figures & Artifacts]
```

1. **Parse Request**: Identify target parameters (e.g., sample rate, filter cutoffs, trigger levels).
2. **Generate Acquisition Script**: Write a script that configures the device and captures raw output.
3. **Generate Analysis Script**: Write a modular, executable script that reads the raw data file, processes signal data, computes metrics, and produces plots.
4. **Execute in Local Environment**: Run both scripts headlessly via local sub-processes.
5. **Verify Output**: Confirm that figures, summary stats, and processed datasets exist and were generated by `analysis.py`.

## Template Directory Structure

Generate and maintain the following directory structure for every run:
```
data/date-stamped folder/
├── config.json          # Experimental metadata & parameters
├── raw_data.hdf5        # Immutable raw data from hardware
├── analysis.py          # Standalone processing script
├── pyproject.toml	     # Pinned Python dependencies
└── outputs/             # Generated figures and processed metrics
```
